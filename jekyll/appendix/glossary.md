# 용어 정의

## 창업 경고·검증

| 용어 | 이 프로젝트에서의 의미 |
|---|---|
| 동×업종 | 판정 단위. 같은 동이라도 업종에 따라 결과가 다름 |
| 비추천 / 조건부 | 표본 가드를 통과한 뒤 강한 신호 2개 이상 / 켜진 신호 1개 이상인 등급 |
| 경고 없음(clear) | 평가 가능한 판정 신호 중 켜진 것이 없음. 성공·안전·추천 보장 아님 |
| 판정 보류(insufficient) | 평가 가능한 판정 신호가 2개 미만. 자료 부족을 경고 없음과 구별 |
| 백분위 | 같은 업종의 비교 가능한 값 중 해당 값보다 작은 값의 비율. 판정 신호는 나쁜 방향이 높도록 맞춤 |
| 코호트 | 일정 기간에 개업한 점포 집단 |
| 백테스트 | 과거 시점 자료로 판정하고 이후 결과와 비교하는 검증 |
| lift | 여기서는 두 집단의 폐업률 비율. 정확도·인과 효과 아님 |
| 표본 가드 | 점포·인구 등 분모가 부족하면 신호를 계산하지 않는 조건 |
| 참고 신호 | 표시하되 등급을 정하는 개수에 포함하지 않는 신호 |

## AI·검색

| 용어 | 의미 |
|---|---|
| LLM | 사실 자료를 바탕으로 설명을 작성하는 언어 모델. 현재 경고 등급 계산기는 아님 |
| RAG | 자료를 검색해 답변의 근거로 제공하는 방식 |
| Hybrid RAG | 초기 과제명·설계의 검색 결합 방향. 현재 코드는 벡터 검색+정형 필터+뉴스 사건 접기로 확인 |
| Chunking | 출처와 검색할 내용을 문서 조각으로 만드는 작업 |
| 임베딩 | 텍스트를 유사도 계산에 쓰는 벡터로 변환 |
| Hit@5 | 상위 5개에 정답이 하나 이상 포함된 질문 비율 |
| Recall@5 | 전체 정답 문서 중 상위 5개로 회수한 비율. 다중 정답에서는 Hit@5와 다름 |
| MRR | 첫 정답 순위의 역수 평균 |
| SSE | 서버가 진행 상황·사실·생성 텍스트를 이어 보내는 방식 |
| 사실 선수집 | LLM 호출 전에 코드가 필요한 지표·판정·근거를 모으는 과정 |
| Latency | 요청부터 응답까지의 지연. 첫 토큰·완료 시간을 나눠 측정 |

## 데이터·설계·자금

| 용어 | 의미 |
|---|---|
| LOCALDATA·인허가 | 개업·폐업 등 행정 기록의 원천 |
| 스냅샷 | 특정 시점의 시설 목록. 목록에서 사라졌다고 확정 폐업으로 단정하지 않음 |
| 브이월드·GeoJSON | 배경지도 타일 제공자 / 서버가 전달하는 경계 도형 형식 |
| BC | 같은 도메인 어휘와 책임을 묶은 코드 경계 |
| 포트·어댑터 | 유스케이스의 인터페이스와 DB·API 등 외부 구현을 나누는 구조 |
| 결정론 계산 | 같은 입력·설정에 같은 결과를 내는 코드 계산 |
| 프리필 | 사용자가 검토·수정할 수 있도록 미리 채운 참고값 |
| 자기자본 외 조달 필요액 | 총 준비자금에서 자기자본을 뺀 금액. 희망대출 승인과 별개 |
| 손익분기 매출 | 고정비와 변동비율을 가정했을 때 비용을 충당하는 매출 |
| 스프린트·WBS | 기간별 작업 묶음 / 작업 분해 구조. 프로젝트 마무리 10/23, 최종 발표 10/27 |
| 완료 기준(DoD) | 구현·검증·문서 반영 등 작업별 완료 조건. 배포 완료와 구별 |

수치와 해석 조건은 [검증 결과와 원문 근거]({{ '/docs/evidence.html' | relative_url }})에 있습니다.
