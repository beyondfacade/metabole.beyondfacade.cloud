# 1) 용어 정의

이 문서 사이트에 나오는 용어를 쉬운 말로 풀었습니다. 비유는 이해를 돕기 위한 것이고, 정확한 정의는 각 문서의 본문을 따릅니다.

## AI · 검색 관련

| 용어 | 쉽게 말하면 |
|---|---|
| **LLM** (거대 언어 모델) | 글을 읽고 쓰는 AI. 이 프로젝트에서는 공고문 요약, 학원 과정명 분류, 최종 분석 답변 작성에 씁니다. |
| **RAG** (검색 증강 생성) | AI가 기억에만 의존해 답하지 않고, 먼저 자료를 검색해서 찾은 근거를 바탕으로 답하게 하는 방식. 오픈북 시험과 같습니다. |
| **Hybrid RAG** | 자료를 찾는 방법을 두 가지 섞은 RAG. 의미가 비슷한 걸 찾는 벡터 검색과, 단어가 딱 일치하는 걸 찾는 키워드 검색을 함께 써서 정확도를 올립니다. |
| **Chunking** (청킹) | 긴 문서나 데이터를 AI가 한 번에 소화하기 좋은 크기의 조각으로 자르는 일. 조각을 잘 자를수록 검색이 정확해지고 빨라집니다. |
| **임베딩** (Embedding) | 글을 숫자 좌표로 바꾸는 것. 의미가 비슷한 글은 가까운 좌표에 놓이므로, "비슷한 내용 찾기"를 계산으로 할 수 있게 됩니다. |
| **인덱싱** (Indexing) | 검색이 빨라지도록 자료에 미리 색인(찾아보기)을 만들어 두는 일. |
| **Recall@5** | 검색 품질 점수. 질문 하나에 검색 결과 5개를 보여줬을 때, 그 안에 정답 자료가 들어 있는 비율입니다. 91.5%가 이 프로젝트의 목표입니다. |
| **Latency** (지연 시간) | 질문을 던지고 답이 돌아올 때까지 걸리는 시간. 40% 줄이는 것이 목표입니다. |
| **에이전트** (Agent) | 한 번 묻고 한 번 답하는 챗봇을 넘어, 스스로 자료를 찾고 계산을 돌려 과제를 끝까지 수행하는 AI. |
| **프롬프트** (Prompt) | AI에게 주는 지시문. 어떻게 쓰느냐에 따라 답변 품질이 크게 달라집니다. |

## 데이터 · 지도 관련

| 용어 | 쉽게 말하면 |
|---|---|
| **API** | 프로그램끼리 데이터를 주고받는 창구. 공공기관이 열어 둔 API를 호출하면 데이터를 자동으로 받아올 수 있습니다. |
| **LOCALDATA** | 행정안전부가 공개하는 전국 인허가 데이터. 어떤 가게가 언제 열고 닫았는지가 담겨 있어, 개폐업률 계산의 뼈대가 됩니다. |
| **전통 변수** | 유동인구, 임대료, 경쟁 점포 수처럼 상권의 기초 체력을 보여주는 변수 8종. |
| **특이변수** | 거리두기, 금리 인상, GTX 개통처럼 상권 밖에서 닥치는 충격을 보여주는 변수 4계층. |
| **브이월드** (VWorld) | 국토교통부가 운영하는 공공 지도 서비스. 배경지도와 행정동 경계를 여기서 받아옵니다. |
| **WMTS / WFS** | 지도를 받아오는 표준 방식. WMTS는 타일 그림으로 된 배경지도를, WFS는 행정동 경계 같은 도형 데이터를 줍니다. |
| **지오코딩** (Geocoding) | 주소를 지도 좌표(위도·경도)로 바꾸는 것. 반대로 좌표를 주소로 바꾸는 것도 포함합니다. |
| **좌표계 변환** (EPSG:5174→WGS84) | 국내 공공데이터가 쓰는 옛 좌표 체계를, 웹 지도가 쓰는 국제 표준 좌표로 바꾸는 작업. 이걸 안 하면 가게 위치가 지도에서 엉뚱한 곳에 찍힙니다. |
| **멱등 시드 / 증분 커서** | 데이터 수집 파이프라인의 안전장치. 멱등 시드는 같은 초기 데이터를 몇 번 넣어도 중복이 안 생기게 하는 것, 증분 커서는 "어디까지 받았는지" 책갈피를 꽂아 새 데이터만 이어받는 것입니다. |

## 프로젝트 진행 관련

| 용어 | 쉽게 말하면 |
|---|---|
| **MVP** (최소 기능 제품) | 핵심 기능만 담아 일단 굴러가게 만든 첫 버전. 완벽한 제품을 오래 만드는 대신, 작게 만들어 빨리 검증합니다. |
| **애자일 스크럼** | 개발 기간을 짧은 구간으로 잘라 계획→개발→시연→반성을 반복하는 진행 방식. |
| **스프린트** (Sprint) | 스크럼의 한 구간. 이 프로젝트는 2주짜리 스프린트 3번과 1주짜리 마무리 스프린트 1번으로 7주를 진행합니다. |
| **칸반 보드** | 할 일을 To Do → In Progress → Review → Done 칸으로 옮겨 붙이며 진행 상황을 한눈에 보는 판. |
| **데일리 스탠드업** | 매일 15분, 어제 한 일·오늘 할 일·막힌 일을 공유하는 짧은 회의. |
| **회고** (Retrospective) | 스프린트가 끝날 때 잘한 것(Keep)·문제(Problem)·시도할 것(Try)을 돌아보는 자리. |
| **DoD** (완료 기준) | "끝났다"고 말할 수 있는 조건. 이 팀은 코드 리뷰 승인 + 테스트 통과 + 문서 반영, 세 가지를 채워야 완료로 칩니다. |
| **GitHub Flow** | 작업마다 브랜치를 따서 PR(풀 리퀘스트)을 올리고, 동료 리뷰를 받은 뒤 합치는 협업 방식. |
