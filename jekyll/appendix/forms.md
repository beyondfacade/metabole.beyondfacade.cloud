# 2) 관련 서식

팀이 반복해서 쓰는 양식이다. 복사해서 채워 쓴다.

## 데일리 스탠드업 기록

[Sprint 일자별 진행 사항]({{ '/docs/schedule/sprint1.html' | relative_url }}) 표에 한 줄씩 쌓는다.

```markdown
| 날짜 | 요일 | 업무 내용 | 담당 | 상태 |
|------|:----:|-----------|------|:----:|
| MM.DD | 요일 | (한 일 / 할 일 / 막힌 일) | 이름 | ✅ 완료 · 🔄 진행 중 · 📋 예정 |
```

## 스프린트 회고 (Keep / Problem / Try)

```markdown
# Sprint N 회고 (MM.DD)

## Keep — 계속할 것
-

## Problem — 문제였던 것
-

## Try — 다음에 시도할 것
-
```

## 데이터 소스 검증 체크리스트

새 데이터 소스를 파이프라인에 붙이기 전에 채운다.

```markdown
# 데이터 소스 검증: (소스명)

- [ ] 인증키 발급 완료, 호출 제한(quota): ___회/일
- [ ] 업종코드 매핑 확인 (인허가명: ___)
- [ ] 좌표계 확인 (EPSG:5174 변환 필요 여부)
- [ ] 기존 데이터와 조인 키 검증 (주소/행정동/좌표)
- [ ] 시계열 커버리지: ____년 ~ 현재, 단절 구간: ___
- [ ] 갱신 주기: 일 / 월 / 분기 → 배치 주기: ___
- [ ] 라이선스·출처 표기 확인 (공공누리 유형: ___)
```

## 정책자금 공고 요약 카드 (표준 필드)

아래는 사람이 공고 원문을 검토할 때 쓰는 양식입니다. 현재 API·화면의 필수 필드 계약이나 LLM 자동 추출 완료를 뜻하지 않습니다. 원문에 없는 한도·금리는 비워 둡니다.

```markdown
- 공고명:
- 기관:
- 대상 업종:
- 대상 지역:
- 대상 단계: 예비창업 / 기창업
- 한도:
- 금리:
- 마감일:
- 원문 링크: (필수)
```

## 측정·검증 기록 양식

```text
확인 날짜 / 저장소 / 브랜치 / 커밋:
질문: 규칙 동작 / 판정 백테스트 / 검색 / 설명 / 성능
원천·데이터 시점:
표본과 제외 조건:
입력 조건·관찰 기간:
실행 명령 또는 원문 결과 파일:
측정값 / 목표 / 가정 (서로 구분):
문제 → 선택 → 이유 → 검증:
해석 한계·미확인 항목:
담당 확인 / 후속 작업:
```
