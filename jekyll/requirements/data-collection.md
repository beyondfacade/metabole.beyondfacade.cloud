# 3) 상권 공공데이터 수집 및 연계

## 경고의 근거가 되는 자료

| 자료 | 구현에서의 용도 | 해석 경계 |
|---|---|---|
| 인허가 개업·폐업 이력 (`store`) | 순유출·생존 코호트·조기 폐업, 점포 마커 | 양도·양수·행정 신고일·좌표 누락 영향 |
| 서울 상권분석 (`commerce`) | 동×업종×분기 매출·점포 집계, 평균 매출 프리필 | 추정매출이며 신규 점포의 예상 매출 아님 |
| 동네 맥락 (`neighborhood`) | 인구·유동·가구·시설·상권 변화, 동네 유형 | 업종 축 없는 값과 업종 실적을 구별 |
| 편의점·어린이집 스냅샷 | 시설·브랜드·정원 현황 | 스냅샷 소실을 확정 폐업으로 보지 않음 |
| 담배소매인 이력·주택 거래 | 편의점 대리 원천·부동산 보조 지표 | 구현했지만 두 업종 모두 판정 재포함 기준 미달 |
| R-ONE·ECOS | 권역 임대료·공실률·금리 참고값 | 동 단위 실계약·개인 적용금리 아님 |
| 기업마당 공고·네이버 뉴스 | 지원 후보·원문 링크·검색 근거 | 후보는 자격 확정 아님, 뉴스는 참고 신호 |

## 적재·조회에서 지키는 구분

일반음식점 API는 하나의 수집 경로로 받고 업태 분류기로 나눕니다. 마스터 시드 18종을 화면의 14종 또는 판정 12종과 혼동하지 않습니다. 좌표계 변환·행정동 매핑·원천 코드 매핑을 거쳐 같은 동·업종끼리 비교합니다. 현재 값만 주는 원천은 별도 테이블과 관측일로 관리합니다.

기업마당 공고는 원천 ID 기반 업서트와 만료 처리를 사용합니다. 여러 공고 API를 모두 운영 중이라는 초기 설명은 사용하지 않습니다. 네이버 뉴스의 제목·발췌·일자·URL을 보관하고 본문으로 연결합니다.

## 자료량과 기준일

`docs/STATUS.md`의 2026-09-28 추가 기록에는 `store` **888,308행**, 업종 지표 **55,093행**이 있습니다. 실시간 개수나 현재 영업 점포 수가 아닙니다. 이번 문서 정비에서 운영 DB를 다시 세지 않았으므로 홈의 실시간 성과 수치로 사용하지 않습니다.

스키마는 [ERD]({{ '/docs/erd.html' | relative_url }})에서 과거 실DB 스냅샷과 2026-10-01 ORM 확인을 나눠 설명합니다. 원문 기준은 [검증 결과와 원문 근거]({{ '/docs/evidence.html' | relative_url }})에 있습니다.

## 추가 수집·확장 조건

새 지역·업종은 원천 제공 범위, 날짜의 의미, 공간조인, 충분한 표본, 라이선스, 판정 검증을 각각 확인해야 합니다. 코드 설정만 추가하면 전국으로 일반화된다고 약속하지 않습니다.
