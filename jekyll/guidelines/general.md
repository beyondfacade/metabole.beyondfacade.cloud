# 1) 일반 사항

## 협업 방식

- **형상 관리**: GitHub(beyondfacade organization)에서 작업마다 브랜치를 따고 PR을 올린다. 동료 리뷰 승인 후에 병합한다.
- **커뮤니케이션**: 매일 15분 데일리 스탠드업에서 어제 한 일·오늘 할 일·막힌 일을 공유한다. 스프린트 종료 시 리뷰(산출물 데모)와 회고(Keep/Problem/Try)를 진행한다.
- **작업 관리**: 스프린트별 칸반 보드로 관리한다. 보드는 [단계별 개발 일정]({{ '/docs/schedule/timeline.html' | relative_url }})에 있다.
- **완료 기준(DoD)**: 코드 리뷰 승인 + 테스트 통과 + 문서 반영. 세 가지를 채워야 완료다.

## 공통 원칙

- **공공데이터만 쓴다.** 권리금처럼 공공에 없는 데이터는 다루지 않고, 개인 식별 데이터는 수집하지 않는다.
- **근거 없는 수치를 출력하지 않는다.** 에이전트가 내보내는 모든 수치는 데이터 소스나 원문 링크가 따라붙어야 한다.
- **문서는 이 사이트에 남긴다.** 결정 사항과 진행 상황은 문서 사이트가 기억한다. 개발 일지는 일자별로 기록한다.
- **가정은 가정이라고 말한다.** LTV 60~70% 같은 가정값, 필라테스 누락 같은 데이터 한계는 화면과 문서에 명시한다.

## 열린 질문의 처리

착수 시점에 확정하지 못한 사항은 문서에 "열린 질문"으로 남기고 팀 논의로 확정한다. 현재 남은 질문:

1. "상권" 단위 정의 — 서울시 상권분석서비스의 상권 영역을 쓸지, 행정동 단위로 할지 (지도 구현은 행정동이 단순하다)
2. 에이전트 응답 형식 — 점수/등급 요약형과 근거 인용형의 비중
3. Recall@5 평가셋(질문-정답 쌍)의 제작 주체와 방법
4. 브이월드 API 키·도메인 등록과 quota 확인 담당자
5. 정책자금 공고 수집 범위 — 자치구 공고까지 포함할지
