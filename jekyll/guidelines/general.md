# 일반 사항

## 협업과 완료 기준

기존 팀 지침은 작업별 브랜치·리뷰·테스트·문서 반영입니다. 문서에는 계획된 운영 방식과 실제 확인한 실행 기록을 구분합니다. 개별 기여는 버전 로그만으로 추정하지 않습니다.

## 공통 원칙

- 현재 구현은 기준 커밋과 코드로, 수치는 날짜가 있는 실험 기록으로 확인합니다.
- 목표·측정값·가정·향후 계획을 구분합니다.
- 경고 없음은 추천이 아니며 보류·제외·자료 없음을 분리합니다.
- 공공 분석 자료와 회원·세션·접속 기록의 개인정보 처리를 구분합니다.
- 초기 구상과 날짜별 기록을 최신 사실로 소급 수정하지 않습니다.

## 문서 동기화

개발 일지 원본은 cloud `docs/jekyll.md`이며 복사본은 자동 동기화됩니다. 원본 정정이 필요하면 해당 저장소의 별도 후속 작업으로 남깁니다. 이번에는 공통 레이아웃의 안내를 사용합니다.

## 확인이 필요한 사항

프로젝트 마무리 10/23·최종 발표 10/27, 팀장과 풀스택 공동 개발 역할, 실제 서비스 주소는 사용자 확인을 반영했습니다. 성능·배포·라이선스·보안 검수는 실제 실행 증거가 있어야 완료로 표시합니다. [검증 결과와 원문 근거]({{ '/docs/evidence.html' | relative_url }})
