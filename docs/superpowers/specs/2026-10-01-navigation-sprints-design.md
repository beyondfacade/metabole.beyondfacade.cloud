# 사이드바와 스프린트 문서 재편 설계

## 목적과 작업 범위

사용자가 지정한 14개 목차를 문서 사이트의 단일 최상위 탐색 순서로 삼는다. 프로젝트 개요와 주제 구성을 합치고, 산출물 내부의 7개 문서를 최상위로 올린다. ERD와 검증 근거는 관련 산출물 아래에서 찾을 수 있게 한다. 설계·기록 후 변경까지 진행하라는 요청에 따라 이 문서와 구현 계획을 작성한 다음 현재 작업 공간에서 구현한다.

## 검토한 방법

1. **산출물 중심 재배치 (선택):** 최상위 14개, 상세 문서 2~3단계. 기존 URL을 유지해 외부 링크와 검색을 보존한다.
2. 메뉴만 숨기기: 변경은 작지만 본문 목차·문서 간 위계가 서로 달라지므로 제외한다.
3. 모든 내용을 14개 파일로 합치기: 긴 설계·ERD·과거 기록까지 합쳐져 읽기와 관리가 어려우므로 제외한다.

## 최상위 탐색과 하위 문서

| 순서 | 메뉴 | 관련 하위 문서 |
|---|---|---|
| 1 | 홈 | 서비스 소개 표지 유지 |
| 2 | 목차 | 같은 14개 순서와 하위 문서 안내 |
| 3 | 프로젝트 개요 | 주제 구성을 본문 통합, 사업 목적·내용·기대 효과 |
| 4 | 팀소개 | 조직 구성 및 역할 분담 |
| 5 | 마일스톤&WBS | 단계별 개발 일정, 그 아래 Sprint 1 기록, 위험 관리 |
| 6 | 요구사항정의서 | 목적·범위·서비스 기능·보안 |
| 7 | 상위 설계서 | 시스템 아키텍처·데이터 수집·RAG |
| 8 | 상세 설계서 | ERD — 데이터 모델 |
| 9 | 시나리오 테스트 | 검증 결과와 구현 근거, 품질 관리 및 테스트 |
| 10 | 최종 검수 | 개발 표준 및 산출물 |
| 11 | 출품시나리오 | 기존 시연 내용 유지 |
| 12 | 개발일지 | 자동 생성 원본 유지 |
| 13 | 부록 | 용어 정의·관련 서식·일반 개발 지침 |
| 14 | 최종산출물 | 기존 실제 화면·설명 유지 |

기존 사업개요·개발요구사항·개발지침·일정·산출물 인덱스 URL은 연결 안내로 보존하고 사이드바에서는 제외한다. 주제 구성 URL은 통합 개요의 해당 절로 안내한다. 연결 안내는 검색 중복을 피하도록 검색에서도 제외한다. 숨겨진 부모 아래에 보이는 자식이 남지 않게 parent/grand_parent를 함께 수정한다.

개발일지는 크론이 덮어쓰므로 `_config.yml` defaults에서 순서와 별도 표시 제목(nav_title)을 넣는다. 테마의 탐색 링크 템플릿은 nav_title이 있으면 표시만 교체하고 부모 탐색은 원래 title을 사용한다.

## 스프린트·칸반

- 마일스톤 페이지에서 로드맵·스프린트별 목표·종료 조건·상태별 카드·WBS를 한 번에 읽는다.
- Sprint 1 08/20~09/02, Sprint 2 09/03~09/16, Sprint 3 09/17~09/30은 기존 기록을 재구성한다.
- Sprint 4 10/01~10/14: 통합 검증·문서 정합성, Sprint 5 10/15~10/23: 최종 검수·인수인계, 발표 준비 10/24~10/27. 후반 세 구간의 작업 분할은 이번 문서 개편에서 제안한 계획임을 표시한다. 확정 날짜는 10/23 마무리·10/27 발표다.
- 기준일은 2026-10-01. 예정·진행·검토·완료의 4열. 완료는 카드에 적은 범위의 기록 확인이며 전체 서비스 배포 완료가 아니다. 착수 기록이 없는 작업은 예정으로 둔다. 빈 열도 '해당 작업 없음'으로 표시한다.
- 카드에는 WBS 식별자·작업명·진행 근거·연결 산출물·종료 조건을 넣는다. 확인되지 않은 개인 배정이나 완료율을 만들지 않는다.
- `_data/project_sprints.yml`이 로드맵·칸반·WBS의 단일 데이터 원천이다. Liquid include가 정적 HTML을 생성한다. JavaScript·드래그 저장·외부 서비스는 필요하지 않다.
- 작은 화면에서는 4열을 1열로 바꾸고, 상태를 색뿐 아니라 제목으로 표시한다. 링크와 접기/펼치기는 키보드로 조작 가능해야 한다.
- 과거 10/8 종료 일정은 기존 `<details>` 안의 기록으로 보존하고 현재 일정은 공통 include에서 표시한다.

## 검증과 완료 조건

Jekyll 빌드, 기존 내부 링크·앵커·이미지·검색 검사, 생성 HTML의 정확한 최상위 14개 순서와 ERD·근거의 부모 연결을 확인한다. 칸반 카드·종료 조건·비어 있는 상태와 모바일 너비를 확인한다. 과거 링크와 자동 생성 개발일지는 유지한다. 설계·계획 문서는 docs/ 아래에 두어 공개 검색에서 제외한다. 실제 서비스 배포나 백테스트 재실행은 이 문서 사이트 변경의 완료 조건이 아니다.
