# 메인 랜딩·최종 산출물 분리 기록

2026-10-01 사용자 후속 요청: 메인 랜딩이 산출물처럼 보이므로 소개 중심으로 다듬고, 실제 구현 화면은 별도의 최종 산출물로 분리한다. 예시 사이트는 구조·표현 참고용이며 메타볼레의 서비스·근거·문구로 구현한다.

## 브레인스토밍에서 정한 방향

기존 홈과 문서 흐름을 바꾸는 범위로 분류했다. 예시의 [홈](https://053.localhostdaegu.cloud/)과 [구현 화면](https://053.localhostdaegu.cloud/showcase/screens/)을 실제 브라우저와 HTML로 확인했다.

| 접근 | 장점 | 판단 |
|---|---|---|
| 문서 요약 중심의 홈 | 근거·기술 정보를 바로 읽음 | 현재 산출물과 겹치는 인상이 남음 |
| 브랜드 소개만 둔 홈 | 첫 인상이 단순해짐 | 심사위원·면접관이 구현 근거로 이동하기 어려움 |
| 서비스 소개 + 별도 구현 화면 | 첫 인상과 상세 검토를 분리하고 서로 연결 | 채택 |

- 메인: 큰 제목·동네 모형 → 핵심 서비스 흐름 → 최종 산출물 안내 → 검증·설계·개발 기록 → 팀·일정.
- 최종 산출물: 실제 화면 4장 → 시연 조건·제공 한계 → 검증 결과·구조·KDT 문서.
- 상세 백테스트·아키텍처를 홈에 반복하지 않고 전용 문서로 연결한다.
- 기존 문서 테마·KDT 계층·permalink 유지. 홈의 색상과 여백은 페이지 범위에서만 조정한다.
- 자료 부족·clear·제외 업종·대안 표시 조건과 실험의 해석 한계는 기존 확인 결과를 유지한다.

## 구현 파일

| 파일 | 변경 |
|---|---|
| `index.markdown` | 소개 중심 랜딩, 홈 메뉴 복원, 실제 화면·상세 수치 이동 |
| `jekyll/showcase/screens.html` | `/showcase/screens/` 최종 산출물, 실제 화면·설명·목차·원본 이미지 링크 |
| `_sass/custom/_presentation.scss` | 메인·산출물 전용 스타일, 홈의 어두운 사이드바, 4폭 반응형 배치 |
| `_sass/custom/custom.scss` | 새 스타일 import |
| `assets/js/docs.js` | 두 전시형 페이지는 일반 문서 목차 래핑에서 제외 |
| `_includes/nav_footer_custom.html` | 최종 산출물 이동 링크 |
| `jekyll/toc.md`, `jekyll/deliverables/index.md`, `demo-scenario.md` | 문서·시연과 최종 산출물 연결 |
| `README.md` | 진입점·스타일·이미지 출처·검증 안내 갱신 |
| `scripts/check-site.py`, `check-search.cjs` | 새 산출물 경로의 검색 색인·검색 결과 검증 |

이전 홈의 주요 앵커 `journey`, `validation`, `architecture`, `decisions`, `documents`는 관련 구역에 남겼다. 홈의 표·화면을 최신 설명처럼 중복 보관하지 않고 이전 상태는 로컬 작업 스냅샷에 보존했다.

## 이미지의 근거

- `seoul-diorama.webp`, `location-pin.webp`: 읽기 전용 cloud 저장소 `frontend/public/landing/`의 기존 메타볼레 일러스트를 복사했다. 예시 사이트의 이미지는 복사하지 않았다. 모형은 실제 지도·판정이 아님을 표시했다.
- `service-entry.png`: 기존 `localhost:3200/`에서 촬영한 입력 전 관문.
- `service-warning-map.png`: 앞선 개편에서 검증한 역삼1동·카페 지도, 판정 산출일 2026-09-30.
- `service-support.png`: 같은 동·업종의 지원 정보. 공고·금리는 촬영 시점 표시값이며 자격·승인 결과가 아니다.
- `service-plan.png`: `budget=50000000`원, 화면의 자기자본 5천만 원. 계산 전 입력 상태이며 결과를 생성한 것으로 표현하지 않았다.

캡처는 2026-10-01, 1440×1000, 기존 로컬 프론트·실백엔드 환경이다. 서비스 서버의 중지·재시작·코드 수정은 하지 않았다. 리포트 생성이나 자금 계산을 이번 촬영에서 새로 실행하지 않았다.

## 검증 결과

- `bundle exec jekyll build` 성공. 기존 테마 Sass deprecation 경고는 남음.
- `git diff --check` 통과.
- `python3 scripts/check-site.py`: HTML 43개·내부 참조 2,966개·오류 0개.
- `node scripts/check-search.cjs`: 기존 4개 검색어와 `최종 산출물` → `/showcase/screens/`까지 5개 통과.
- 홈·최종 산출물을 375·768·1152·1440px에서 검사: 8개 조합 모두 페이지 가로 넘침 0px, 깨진 앵커·이미지 없음. 지연 로딩 이미지는 실제 스크롤과 decode 완료 후 검사했다.
- 첫 검증에서 1440px의 일러스트 넘침 23px와 밝은 헤더의 GitHub 링크 색상을 발견해 수정했다. 지연 로딩 전 이미지를 미로딩으로 판정하던 검증 스크립트는 스크롤 후 판정하도록 바로잡았다.
- 독립 검토의 Critical/Important 없음. Minor인 홈 사이드바 hover 대비와 카드 보조문구 대비는 수정했다.
- 기존 `jekyll.md` SHA-256 `7873fda4e33070cea3cd9a73d23db042a559818839d75ed25964a8965cdd3d9e` 유지, cloud 작업 트리 깨끗함.

로그·스크린샷·브라우저 측정값은 `/tmp/metabole-landing-redesign/`에 임시 보관한다. 앱 전체 동작·공개 배포의 검증 완료를 주장하지 않는다. 커밋·푸시·배포는 수행하지 않았다.

추가 화면 동작 검사: 메인 CTA → 최종 산출물, 모바일 메뉴 → 최종 산출물, 자금 계획 목차 → 해당 제목(화면 상단 약 32px), 원본 이미지의 키보드 열기를 확인했다. 탐색 완료 전 위치를 읽거나 URL 대기에 맞지 않는 패턴을 쓰던 검사 스크립트는 완료 후 확인하도록 수정했다. 중첩 링크는 없고, 메인에는 실제 앱 캡처가 남아 있지 않다.
